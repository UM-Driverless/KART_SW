STATE Topbar chip 1 — autonomous-system state from the state machine, highlighted while it is RUNNING
MISSION Topbar chip 2 — selected mission. REMOTE_CONTROL is the one that hands driving to a human over the network
HB Topbar chip 3 — seconds since the last ESP32 heartbeat. Green while they keep arriving, red "HB LOST" once they stop, "HB --" before any has been seen
SYS Topbar chip 4 — worst case of the readouts below, naming where the trouble is instead of only changing colour. Red for a tripped or unreadable steering sensor, low heap, any stack under 200 bytes, or a missing ESP32; amber for slow YOLO or ESP frame rates. I2C and AGC are left out on purpose — they are never populated on this board, so folding them in would peg the chip to a permanent false alarm

STEER Steering sensor (MT6701 read over PWM). OK, NO SIGNAL, or TRIPPED = latched fault, EBS fired, throttle refused until the ESP32 reboots
I2C Legacy AS5600-over-I2C bus. N/A on this board — the ESP32-S3 firmware does not poll an AS5600
HEAP Free heap memory on ESP32 (KB)
AGC AS5600 Auto Gain Control (0–255, ideal 20–235). N/A on this board for the same reason as I2C
STK Min free stack bytes: comms / control / heartbeat / health. Red if <200
YOLO YOLO inference rate (Hz). Green >30, yellow 15-30, red <15
ESP ESP32 steering-frame rate over USB serial (Hz). Firmware target 100. Green ≥80, yellow 30-80, red <30
